# 青龙 CPU 性能与验证报告

本报告的主体保留早期六级双发射 RV32IM CPU 的 RTL 仿真和 PDS 验证数据。**2026-10-22 已完成当前优化配置的 27 MHz 实板 smoke 与 CoreMark performance 测试**：2000 次迭代为 396,619,914 周期，三项 CRC 通过，CoreMark/MHz 为 5.042611；按板载 27 MHz 标称时钟换算约 136.150501 CoreMark。两次成功的实板结果与同固件 RTL 仿真周期完全一致。当前配置、编译参数、资源、原始证据与复现命令见[上板调试记录](上板调试记录.md)。下表与后续早期结果不能直接当作当前配置成绩。

| 项目 | 配置 |

| CoreMark | EEMBC 上游 `1f483d5b8316753a742cbf5590caf5bd0a4e4777`，算法文件未修改 |
| riscv-tests | 上游 `3df703cd52d5f0d8224e3c50bf03c6cb70efff98` |
| 基准数据 | 单上下文、静态分配、2000 字节，performance / validation 两组种子 |

计时读取 64 位 `mcycle`，高/低/高读取避免 RV32 回卷问题。`MEASURED_CYCLES_HEX` 保留完整计时结果。计时区间位于 CoreMark 的 `start_time()` / `stop_time()` 之间，不含启动和随后打印；日志末尾的 `SIM cycles` 是整个程序的周期数，两者不应混用。

## CoreMark 周期对照

以下均为相同编译选项、10 次 performance 迭代：

| 配置 | 计时周期 | 等效 CoreMark/MHz | 相对初始单发射 |
| --- | ---: | ---: | ---: |
| 单发射，Load 等待 WB | 4,125,412 | 2.424000 | 基线 |
| 双发射，Load 等待 WB | 3,731,754 | 2.679705 | +10.55% |
| 双发射，Load 响应旁路 | 3,464,404 | 2.885646 | +19.04% |

双发射提升来自独立 ALU 指令与第一通道共同执行；Load 旁路减少相关停顿。双发射不是每周期都提交两条：分支、串行指令、同组 RAW/WAW 冲突以及单个数据端口都会限制配对率。

10 次迭代默认配置的全程序统计：3,490,079 周期、3,017,237 条退休指令、518,521 次第二通道退休、586,584 次控制流指令、69,126 次预测失误、267,491 次 Load 相关停顿。整个运行的 IPC 约 0.865；峰值双发射能力不能替代实际工作负载 IPC。

短测试用于快速对比。上游会因不足 10 秒显示 duration error；脚本单独核对三个算法 CRC，只允许该持续时间不足，不忽略其他错误。

## 长迭代验证

使用 `ITERATIONS=1000 CPU_HZ=27000000`：

| 种子 | 计时周期 | 等效 CoreMark/MHz | 按 27 MHz 换算的计时区间 | 校验 |
| --- | ---: | ---: | ---: | --- |
| performance | 346,529,413 | 2.885758 | 12.834 秒 | 三项 CRC 通过，上游显示 Correct operation validated |
| validation | 348,074,955 | 2.872944 | 12.892 秒 | 三项 CRC 通过，上游显示 Correct operation validated |

performance 参考 CRC 为 `e714 / 1fd7 / 8e3a`，validation 为 `e3c1 / 0747 / 8d84`，分别对应 list、matrix、state。

当前移植层使用 `HAS_FLOAT=0`，上游打印的秒数和 `Iterations/Sec` 有整数截断。性能计算应采用完整周期：

```text
CoreMark/MHz 等效值 = iterations × 1,000,000 / measured_cycles
指定时钟下的迭代/秒 = iterations × CPU_HZ / measured_cycles
```

例如 performance 长测试按 27 MHz 换算约 77.915 次/秒。此数值是仿真换算，不能作为实际板上 27 MHz 测量值。更不能将高频约束目标乘以该数值后宣称已达到相应板上 CoreMark。

## FPGA 资源与时序

ADS 综合的当前默认双发射配置资源如下，使用 `sw/smoke.c` 固件。报告范围为整个 `qinglong_fpga_top`，包含 CPU、TCM 和最小外设：

| 资源 | 用量 | 芯片占比 |
| --- | ---: | ---: |
| LUT | 6,140 | 9.22% |
| 寄存器 | 2,762 | 2.07% |
| DRM36K | 48 | 30.97% |
| APM / DSP | 4 | 1.67% |
| 锁存器 | 0 | — |

其中 CPU 层次约 5,853 LUT、2,506 寄存器、4 APM；TCM 为满足两条取指和一个数据读口，综合器复制了存储。这解释了逻辑容量仅 64 KiB、物理 DRM 用量却更高的原因。退休调试接口未连接到板级 IO，相关观测逻辑会被综合裁剪。

## 功能验证范围

| 验证 | 结果与范围 |
| --- | --- |
| 裸机 smoke | C 启动、运算、访存、UART 文本、退出码 |
| RV32UI / RV32UM | 49 项上游汇编测试；`ma_data` 要求直接支持非对齐访问，本核改为精确异常，另有专项测试 |
| 异常和 CSR | 15 类场景，含非法指令、ecall、ebreak、地址对齐、访问错误、只读 CSR、mret |
| 中断 | 外部/软件/定时器优先级、向量入口、MIE/MPIE 恢复、计数器冻结与 RV32 半部写入 |
| 双发射专项 | 15 组场景，含 RAW/WAW/WAR、两路旁路、x0、访存/乘除配对、分支、成组撤销和取指边界 |
| 随机等待差分 | 52 个程序 × 3 个总线种子，共 156 轮；检查 81,864 条退休指令，包含 11,841 条第二通道退休 |
| UART 波形 | 六种字节的 8N1 帧，逐周期核对 234 周期/bit、忙时输入保持、帧中复位 |
| PDS 主工程 | 实际读取 `RiscV.pds` 并完成 Compile，非仅检查文件是否存在 |

差分参考模型独立执行整数指令并比较提交 PC、指令、寄存器和结果。总线随机等待包含取指 1～6 周期、数据 1～8 周期和请求背压。CSR 读取值在差分中透传，特权行为由专用汇编测试覆盖；本回归不等价于完整架构认证或形式验证。

## 复现命令

WSL：

```bash
cd /mnt/d/FPGA/RiscV
make deps
make check
make coremark DUAL_ISSUE=0 LOAD_BYPASS=0
make coremark DUAL_ISSUE=1 LOAD_BYPASS=0
make coremark DUAL_ISSUE=1 LOAD_BYPASS=1
make coremark ITERATIONS=1000 CPU_HZ=27000000
make coremark ITERATIONS=1000 CPU_HZ=27000000 VALIDATION=1
```

PowerShell：

```powershell
Set-Location D:\FPGA\RiscV
.\scripts\sync_pds_project.ps1
.\scripts\build_fpga.ps1 -PlaceRoute
```

原始运行日志保存在 `build/`。最终选用的报告摘要和原始工具报告保存在 `docs/results/`，以便核对数值。

## 当前代价和下一步

双发射增加了译码、寄存器读写、旁路和取指存储成本。Load 响应旁路改善每周期吞吐，却延长存储到 EX 的路径，因此需要同时比较 MHz、CoreMark/MHz 和资源。不能仅凭 IPC 增加认定最高主频下的总吞吐一定更高。

当前已完成 27 MHz 原始时钟下的板级下载、真实 UART 启动与 CoreMark performance 长迭代验证，详见上板调试记录。高频 PLL 稳定性、validation 种子实板长测、断电启动及最终竞赛测试条件仍需分别验证。之后可继续优化分支重定向路径、寄存器文件/旁路结构和存储读口，再加入 Cache / DDR、OS 与 AI 加速器。

参考：[EEMBC CoreMark 源码和报告规则](https://github.com/eembc/coremark)、[RISC-V 测试](https://github.com/riscv-software-src/riscv-tests)、[RISC-V 机器态规范](https://docs.riscv.org/reference/isa/priv/machine.html)。
