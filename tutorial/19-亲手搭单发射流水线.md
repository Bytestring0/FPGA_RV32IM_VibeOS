# 19. 亲手搭一条单发射流水线

第 17 章的多周期核心一次只处理一条指令：先取指，执行完，等访存，退休，再开始下一条。这很直观，但真实项目可以在 MEM 等待一条指令时，让另一条指令待在 EX，让前端继续取指。

这一章给你一份可以编译和测试的过渡实现：[pipeline_core.sv](examples/10-pipeline-core/pipeline_core.sv)。我们沿着代码把多周期状态机拆成多个能独立暂停的有效位，再通过定向测试理解依赖、flush 与更老访存错误。

**不要误认成最终青龙**：它使用项目现成的译码器和 ALU，只有单发射、保守 RAW 暂停、单项指令缓冲；没有预测器、旁路、双发射、M 扩展或 CSR/机器态陷阱。错误只置 `fault` 停机。指令响应的第二个字也被忽略。它的目的是让你有一个可运行的流水化起点，再把第 7～12、16 章的真实项目功能逐项加上。

## 19.1 先运行，再阅读

从项目根目录运行求和与分支测试：

```powershell
iverilog -g2012 -s pipeline_tb -o "$env:TEMP\pipeline.vvp" `
  rtl/rv32_pkg.sv rtl/rv32_decode.sv rtl/rv32_alu.sv `
  tutorial/examples/10-pipeline-core/pipeline_core.sv `
  tutorial/examples/10-pipeline-core/pipeline_tb.sv
if ($LASTEXITCODE -ne 0) { throw '编译失败' }
vvp "$env:TEMP\pipeline.vvp"
if ($LASTEXITCODE -ne 0) { throw '仿真失败' }
```

本次运行输出 `PASS pipeline_core: retired=23 sum=15 stores=1 cycles=163`。这里最后的周期统计包含测试台在故障后额外等待的几拍，与多周期实验的 160 不能直接当作严格性能对比；该前端保守、内存延迟与分支也会遮盖流水线吞吐收益。

再运行冲刷与故障专项：

```powershell
iverilog -g2012 -s pipeline_flush_tb -o "$env:TEMP\pipeline_flush.vvp" `
  rtl/rv32_pkg.sv rtl/rv32_decode.sv rtl/rv32_alu.sv `
  tutorial/examples/10-pipeline-core/pipeline_core.sv `
  tutorial/examples/10-pipeline-core/pipeline_flush_tb.sv
if ($LASTEXITCODE -ne 0) { throw '编译失败' }
vvp "$env:TEMP\pipeline_flush.vvp"
if ($LASTEXITCODE -ne 0) { throw '仿真失败' }
```

预期 `PASS pipeline_flush: wrong-path store suppressed; older load error suppresses younger store`。编译时 Icarus 可能输出敏感度拓宽提示；仍应检查退出码和 PASS。

## 19.2 让状态同时存在

多周期核心只有一个 `state`，表示全系统此刻在 IF、EXEC 或 D_RSP。流水线改为让各阶段有自己的有效位：

```systemverilog
logic q_valid;  // 一笔取指请求在途
logic f_valid;  // 一条已返回指令在前端缓冲
logic x_valid;  // EX 中有一条指令
logic m_valid;  // MEM 中有一条指令
logic w_valid;  // WB 有一条等待观察的退休记录
```

这些位可以同时为 1，各自代表**不同年龄**的指令。例如：

```text
q_valid=1：较年轻，内存正准备返回 PC=0x0c
f_valid=1：PC=0x08，等待发射
x_valid=1：PC=0x04，正在算或等待
m_valid=1：PC=0x00，正在等 Load 响应
```

具体实验的前端一次只允许一个指令缓冲，并不保证上述每种组合都会同拍出现；这个图说明年龄关系。`valid=0` 的 payload 不参与架构行为，不需要把每个数据寄存器都清零。

## 19.3 一条指令随阶段携带自己的信息

这份实现中，EX 保存：

```systemverilog
logic x_valid, x_error;
logic [31:0] x_pc, x_insn, x_a, x_b;
decode_t x_dec;
```

MEM 保存：

```systemverilog
logic m_valid, m_sent, m_load, m_store, m_write;
logic [31:0] m_pc, m_insn, m_addr, m_data, m_result;
logic [4:0] m_rd;
logic [2:0] m_funct3;
```

如果你读到 `m_addr`，它属于 MEM 当前那条指令；此时 `x_dec` 可能已属于另一条。不能用当前 EX 的 funct3 去解释 MEM 的 Load 响应，因此宽度和原始地址要一起保存。

WB 则保存该指令的 PC、机器码、rd、最终结果与写使能；这些字段被输出到退休接口。更完整的项目还保存预测值、异常、CSR、乘法和第二通道字段，见 [核心状态声明](../rtl/rv32_core.sv#L84-L144)。

## 19.4 先从 MEM 的出口倒着写 ready

```systemverilog
assign m_finish = m_valid &&
    (!(m_load || m_store) || (d_rsp_valid && d_rsp_ready));
assign m_ready = !m_valid || m_finish;
assign x_go = x_valid && m_ready && !mem_error && !fault;
assign x_ready = !x_valid || x_go;
```

逐个读：

- 普通 ALU 到达 MEM 后，不必等数据总线；访存必须等响应被接收。
- MEM 为空或本沿将完成时，可以接收 EX 新指令。
- EX 有效、MEM 能接收、且没有更老的内存错误时，EX 可推进。
- EX 为空或本沿将推进时，可让前端发射新指令。

考虑一次同拍替换：沿前 MEM 是 A，EX 是 B；若 A 完成且 B `x_go=1`，沿后 WB 捕获 A、MEM 捕获 B。代码中两个寄存器组在同一个上升沿用非阻塞赋值，右侧都读取沿前值，不会让 WB 意外拿到 B。

这是简化公式。真实青龙还要考虑 Load 旁路 hazard、乘除完成、early LSU 请求接收、中断、CSR/serial 和双通道，不能只复制这一小段作为最终控制。

## 19.5 MEM 如何确保请求不重复

代码只在 MEM 的访存有效且尚未发出时发请求：

```systemverilog
assign d_req_valid = m_valid && (m_load || m_store) && !m_sent && !rst && !fault;
assign d_rsp_ready = m_valid && m_sent && !rst;
```

`d_req_valid && d_req_ready` 后将 `m_sent` 置 1；之后等待响应，不再发送同一 Store。MEM 不 ready 时，其地址、写数据、宽度和控制都保持，因此被背压时数据请求稳定。

当旧指令完成、同时有新指令进入 MEM 时：`m_valid` 更新为新指令有效、`m_sent` 清零，表示新访存尚未发出。这份示例把请求留在 MEM，避免 early LSU 的额外竞态；它也因此不能模拟项目 `EARLY_LSU=1` 的同拍请求重叠。

## 19.6 保守地处理 RAW 依赖

EX、MEM、WB 中有较老的写者时，前端如果读取相同的非零 rd，就等待：

```systemverilog
hazard = (x_valid && x_dec.reg_write && reads_rd(f_dec, x_dec.rd)) ||
         (m_valid && m_write && reads_rd(f_dec, m_rd)) ||
         (w_valid && w_write && reads_rd(f_dec, w_rd));
```

`reads_rd` 同时检查 `use_rs1/use_rs2`。例如：

```asm
addi x5,x0,7
add  x6,x5,x5
```

ADD 在前端时会先等 ADDI 走过 EX、MEM、WB。WB 有效的那一拍也继续等，因为寄存器写入发生在该沿；下一拍读取数组时才能看到新值。这样无需同拍 WB 读写旁路，比较慢但思路清楚。

检查 `rd!=0` 是必要的：写 x0 不会改变它，因此不能制造真实数据依赖。等这个保守版本通过后，按照第 8、16 章先加 WB→读口旁路，再加 MEM/WB→EX；每次增加功能都要缩小等待并单独验证，不要先把 hazard 删除。

## 19.7 前端请求和在途上下文

```systemverilog
assign i_req_valid = !q_valid && !f_valid && !flush && !fault && !rst;
assign i_rsp_ready = q_valid && (q_killed || !f_valid || flush || fault) && !rst;
```

一次请求接收时保存 `q_pc` 并使 `q_valid=1`，下一顺序 PC 变成 `f_pc+4`。响应握手时，若没有被 kill，保存指令、PC 和错误位到 f 缓冲；队首发射后 `f_valid=0`。

这个实现刻意不支持“消费旧响应同拍接受新请求”，也只保留一个缓冲；因此性能较低，逻辑却容易看清。真实项目有四项队列、两字响应、预测上下文和请求/响应重叠。第 7 章及 [第 16 章队列实验](16-核心组装施工手册.md#167-第六个里程碑写前端队列并单发射) 是下一步。

## 19.8 处理分支：先默认顺序，错了就 flush

在 EX，计算：

```systemverilog
next_pc = taken ? target : x_pc+4;
branch_redirect = x_go && !x_fault && next_pc != x_pc+4;
```

前端总是假设下一 PC 是顺序地址。若指令实际跳转到不同目标，`branch_redirect` 在指令真正离开 EX 时生效：

```systemverilog
if (flush) begin
    f_valid <= 0;
    if (q_valid && !i_consume) q_killed <= 1;
    if (branch_redirect) f_pc <= next_pc;
end
```

已经放进 f 缓冲的年轻指令被清掉；已经接收但还没响应的请求不能当成不存在，要标记 killed，等待并丢掉其响应。重定向当拍 `issue=0`、`i_req_valid=0`，防止错误路径在边界继续进入。

专项测试故意让一条较老 Load 延迟，使后面的分支在 EX 等待，同时前端接受错误路径的 Store 取指。Load 成功后分支跳到正确目标，测试检查错误路径确实曾被取到、但 Store 接收次数为 0。没有这个覆盖计数时，“Store 次数为 0”可能只是因为测试从未取到错误路径。

## 19.9 更老 Load 报错时，年轻 Store 不能发

第二个专项用例：

```asm
addi x1,x0,0
lw   x2,0(x1)      # 总线返回错误
sw   x1,4(x0)      # 年轻 Store
```

年轻 Store 可以在 EX 等待，但较老 Load 仍占 MEM；待 Load 返回错误时：

```systemverilog
mem_error = m_finish && (m_load || m_store) && d_rsp_error;
x_go = x_valid && m_ready && !mem_error && !fault;
fault_now = mem_error || (x_go && x_fault);
```

`!mem_error` 禁止这拍把年轻 Store 推进到 MEM；`fault_now` 清除年轻前端和 EX 并停止。本例把故障简化为 HALT；真实项目要产生正确的 `trap_pc/cause/value`，让较老已提交状态保留并跳到 handler。

测试台断言该场景只有开头的 ADDI 退休，Store 接收次数为 0。它不能证明任意错误条件都正确，也不能证明真实外设在自己返回错误时不会已经发生副作用。

## 19.10 退休什么时候发生

MEM 正常完成时捕获到 WB：

```systemverilog
w_valid <= m_finish && !mem_error;
if (m_finish && !mem_error) begin
    w_pc <= m_pc; w_insn <= m_insn; w_rd <= m_rd;
    w_result <= mem_result; w_write <= m_write;
end
```

随后 `retire_valid=w_valid`，WB 的 PC/insn/rd/data 就可以给参考模型。Load 的 `mem_result` 是字节选择和扩展后的值；ALU 则是 EX 保存的结果。每拍覆盖 `w_valid`，不会因为下游不动而重复退休。

本示例发生 `fault` 后，已经进入 WB 的较老指令仍可能在接下来一拍退休；测试台特意等几拍再检查。不要假定一看到 fault 就把所有年长指令的合法结果也抹掉。完整项目的异常与双发射退休更复杂，第 10、11 章有年龄实例。

## 19.11 接下来按什么顺序改

建议在自己的副本中依次做下列练习，每次运行两份现有测试并补新的断言：

1. 为求和程序检查每次退休的 rd 和 data，而不仅是 PC 和最终数组。
2. 让指令/数据响应延迟随种子变化，并在 valid 背压时检查请求载荷稳定。
3. 增加负偏移、所有合法字节/半字访问；检查非目标字节未改变。
4. 加 WB 同拍旁路，缩短一拍等待；用两次覆盖同一个 rd 的程序检查最新值。
5. 给 EX 加 MEM/WB 旁路；构造长 stall 跨越 WB 消失的测试。
6. 将前端单项缓冲替换成四项队列，保存两个响应字和各自错误位。
7. 引入 CSR、同步异常与中断，先在单发射下验证精确边界。
8. 引入乘除、预测及双发射，并按第 16 章的真实源码逐段对照。

这份 160 多行教学核心和第 16 章清单之间，仍有大量实现和测试工作。不要把它的两项 PASS 或教学波形当成完整项目通过，更不能当成赛题全部要求完成。
