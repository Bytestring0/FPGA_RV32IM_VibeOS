# 8. 先写单发射流水线，再考虑双发射

你现在有译码、ALU、寄存器堆和取指队列，下一步要让多条指令同时处于不同阶段。不要马上做两条同时发射：先只发一条，建立正确的暂停、旁路和异常控制。单发射逻辑稳定以后，双发射主要是在同一个程序顺序中并行处理符合条件的一对指令。

本章先讲可以亲手实现的保守流水线，再逐项对照 [rv32_core.sv](../rtl/rv32_core.sv) 的优化。涉及总线的详细字节操作留到第 9 章；本章把 MEM 看成一个可能多周期才能完成的阶段。

## 8.1 为什么把工作拆成六级

如果一条指令在一个周期完成“取指 → 译码 → 读寄存器 → 运算 → 访问数据内存 → 写寄存器”，时钟周期至少要容纳最长的组合路径；真实 FPGA 的内存也通常不是零延迟。把工作拆成阶段，允许不同指令在不同阶段并行：

```text
IF1  决定取指地址并请求
IF2  等响应、预译码并放入取指队列
ID   队首译码、依赖和发射判定
EX   选操作数、算术、分支/地址/异常判定
MEM  等访存或多周期结果，确定异常和结果
WB   依程序顺序产生退休、更新寄存器
```

这里的阶段是逻辑分工，不保证每个阶段总是恰好一个时钟；总线等待、除法、数据依赖和冲刷都会改变停留时间。代码中的队列还使 IF2 与 ID 之间不是一个固定深度的简单寄存器。

## 8.2 每级不仅保存数据，还要保存“是否有指令”

先用一条普通 `addi` 举例。进入 EX 的信息至少包括：

```text
x_valid：这一级当前是否装有指令
x_pc：这条指令自己的 PC
x_insn：原始指令（便于异常和退休观察）
x_dec：译码控制及 rd/rs/立即数
x_pred：当初预测的下一 PC
x_a/x_b：从寄存器堆读出的两个值
x_error：取指错误
```

进入 MEM 时，还要保存结果、原始有效地址、Store 数据、目的寄存器、访存宽度、异常 cause/tval 等。进入 WB 时，至少保存 PC、指令、rd、写使能和最终结果。

一条气泡可以用 `valid=0` 表示；数据寄存器里的旧数无需清零，但所有副作用必须受 valid 门控。否则 reset 后或 flush 后，残留的旧 Store 控制仍可能写设备。

## 8.3 从单级握手推导 `ready`

设某一级保存一条指令，满足 `valid && can_finish` 就会在本沿向后推进。为了决定能否覆盖当前级，我们定义：

```text
该级 ready = 当前为空 OR 当前指令本沿能离开
```

项目对应 [MEM/EX 控制](../rtl/rv32_core.sv#L381-L438)：

```systemverilog
m_ready = !m_valid || m_finish;
x_ready = !x_valid || x_go;
```

注意名称含义：`m_ready` 表示 MEM 当前为空或即将完成，可以接受 EX；它不是外部内存的 `d_req_ready`。同样 `x_ready` 表示 EX 可以接受新指令。

常见的时序模板是：

```systemverilog
if (reset) begin
    stage_valid <= 0;
end else if (flush) begin
    stage_valid <= 0;
end else if (stage_ready) begin
    stage_valid <= incoming_valid;
    if (incoming_valid) stage_payload <= incoming_payload;
end
```

如果 `stage_ready=0`，原指令和它的所有字段保持。这个模板展示原则，不是可直接替换项目的代码：项目不同阶段的 flush 优先级、同拍事务、数据旁路与异常需要单独处理。

## 8.4 为什么暂停不能只冻结 PC

假设一条 LW 在 MEM 等待响应：

```text
MEM: lw x5,0(x1)   （响应尚未回来）
EX : add x6,x5,x5  （想读取 x5）
ID : sw x6,4(x1)
```

如果只停止 `f_pc`，但 EX 下一拍仍然把 ADD 替换成 Store，就丢了一条指令；如果 EX 继续算旧的 x5 并写回，又会得到错误结果。正确行为是 MEM 继续等待，EX 中的 ADD 和其必要字段保持，ID/队列也不能覆盖它。取指端能否继续请求还取决于队列剩余空间，但这与后端能否推进是不同的问题。

项目通过 `m_finish/m_ready/x_go/x_ready/id_issue` 将这种背压从后往前传递。读 RTL 时先找这几根线，再追溯每个字段更新条件，通常比先看六百行变量定义容易。

## 8.5 从最慢但最安全的依赖处理开始

对于：

```asm
addi x5,x0,7
add  x6,x5,x5
```

如果 ADD 在 ID 读到 x5，而 ADDI 尚未写回，就会读到旧值。第一版可以采用保守规则：只要 EX/MEM/WB 有更老的有效写寄存器指令，其 rd 与当前要用的 rs 匹配且非零，就暂停 ID，等写回再发。必须检查 `use_rs1/use_rs2`，否则会对不使用的字段制造假依赖。

这版慢，但更容易建立正确的退休流。写一条有依赖的程序，一条完全独立的程序，在随机等待下检查 PC 和结果；稳定后再加旁路。

## 8.6 增加旁路：最近的较老写者优先

旁路不是修改寄存器堆，而是在 EX 的操作数入口选取一个更近的新值。看下面三个写者和消费者：

```asm
addi x5,x0,1    # 更老
addi x5,x0,2    # 更新的写者
add  x6,x5,x5  # 该读取 2 而不是 1
```

消费者在 EX 时，第二条可能在 MEM，第一条可能在 WB。应选择离消费者最近的较老写者，也就是 MEM 中的 2，而不是 WB 中的 1。一个单发射的概念实现：

```text
a = x_a                         # 发射时从寄存器堆读到的值
如果 WB 有效且写 rd==rs1：a = WB 结果
如果 MEM 有效且写 rd==rs1 且结果可用：a = MEM 结果
如果 rs1==0：a = 0
```

由于后一个选择覆盖前一个选择，MEM 优先于 WB。rs2 同理。项目 [245–275 行](../rtl/rv32_core.sv#L245-L275) 正是通过一系列条件覆盖实现优先级，同时支持两条物理通道。注意这只是数据选择，还必须另用 `hazard/m_ready` 保证未完成的 Load/乘法不会被当作可提交结果。

## 8.7 Load-use 冒险：旁路线存在不等于数据已准备好

考虑 `lw x5,...; add x6,x5,x5`。MEM 中的 Load 如果还没有响应，`mem_result` 可能不是最终数据。项目允许组合数据路径提前选取 `mem_result`，但同时通过：

```systemverilog
hazard = m_valid && m_write_rd && m_rd != 0 &&
         ((m_load && !(LOAD_BYPASS && m_finish && !mem_trap)) || m_mul) &&
         ((x_dec.use_rs1 && forward_m0[0]) ||
          (x_dec.use_rs2 && forward_m0[1]) || ...);
```

以及 `x_go` 对 `!hazard`、`m_ready` 的要求阻止结果被真正推进。`LOAD_BYPASS=1` 时，成功的 MEM Load 响应可供 EX 使用；关闭后要等更晚的写回。错误响应产生 `mem_trap`，不能把错误数据当作成功值交给年轻指令。

设计自己的第一个版本时可以完全不做 Load 响应旁路，直到 WB 后再让消费者前进；速度慢但易验证。加入优化时要分别测试响应成功、响应错误、等待长短、旁路开关和紧随 Load 的分支/Store。

## 8.8 一个不容易发现的坑：暂停时间比 WB 旁路还长

假设消费者在 EX 被别的原因暂停。某个周期它从 WB 旁路拿到正确操作数；下一周期该 WB 指令离开，但消费者仍然卡在 EX。如果 EX 内保存的 `x_a` 仍是最早读取的旧值，旁路源消失后就会退回旧值。

项目在 EX 保持时保存当前已经旁路后的操作数：

```systemverilog
end else if (x_valid) begin
    x_a <= a; x_b <= b;
    x_second_a <= a_second; x_second_b <= b_second;
end
```

对应 [601–605 行](../rtl/rv32_core.sv#L601-L605)。测试时可安排“WB 提供操作数 + EX 因下游或除法继续停顿”并故意让停顿超过一个周期；这类 bug 往往只在随机内存等待中偶现。

## 8.9 项目为什么提前比较寄存器编号

一个直接实现可以每周期在 EX 组合比较 `x_rs1 == m_rd`、`x_rs1 == w_rd`。但寄存器编号比较、valid 判断、结果多路选择、ALU 运算可能都落在同一条关键路径。

项目 [145–179 行](../rtl/rv32_core.sv#L145-L179) 在前一阶段准备 `forward_m0/m1/w0/w1` 的匹配位，四个操作数对应主/辅助通道各自的 rs1/rs2。EX 真正使用时仍检查对应阶段是否有效、是否写寄存器和结果是否可用。

尤其注意 `x_ready` 为假时比较的是**被暂停的 EX 操作数编号**，而不是新 ID 编号；`m_ready` 为假时也必须使用保持中的 MEM 写目标。优化这种比较不能只照搬布尔公式，先为“推进、停住、同拍替换”三种情况画出沿前/沿后状态。

## 8.10 指令什么时候才算真正完成

项目的 `m_finish` 概念是：MEM 有效，且普通算术可以完成、异常可以报告、或访存响应已被接收；高位乘法还要等其结果准备好。之后生成 WB 的 valid 和结果。

WB 是程序顺序的可观察提交点：

```systemverilog
assign retire_valid = w_valid;
assign retire_pc = w_pc;
assign retire_insn = w_insn;
assign retire_rd = w_write_rd ? w_rd : 5'b0;
assign retire_data = (w_write_rd && w_rd != 0) ? w_result : 32'b0;
```

Store、branch 等即使不写 rd，也会正常退休，`retire_rd=0`。这一输出让验证端独立比较每条指令，而不必猜测 CPU 内部每一拍。

但 Store 的外部副作用可能在退休之前的请求接收时发生，因此必须保证**所有可能取消这条 Store 的更老异常已得到处理**；只在 WB 屏蔽写寄存器是不够的。这个关键约束留到下一章详细处理。

## 8.11 按阶段做哪些测试

先不启用双发射和预测。分别准备：

1. `addi` 连续写不同寄存器，观察正常吞吐和退休顺序。
2. RAW：生产者后紧跟消费者，检查第一条不同间距、不同寄存器。
3. 连续两次写同一个 rd 后读取，确认选择最近写者。
4. 向 x0 写入后读取 x0，确认从任何旁路都仍是零。
5. Load 后紧跟 ADD/Store/BEQ；随机增加响应延迟。
6. 在长等待时观察每级 PC、valid 和字段都稳定；恢复后既不丢失也不重复退休。
7. 错误响应与错误路径 Store：必须进入预期陷阱，不得产生年轻副作用。

每个用例先画预期退休 PC/rd/data，再查看波形。项目的差分测试实际还会检查指令、内存与双退休，见 [第 14 章](14-验证与调试.md)；这里的用例只是建立局部信心。
