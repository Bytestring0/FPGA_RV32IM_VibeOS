# 6. 寄存器堆和 ALU：算出正确的值，再把它交给正确的人

译码器已经说出“读 x5、读 x6、执行 SUB、写 x7”。这一章我们写接受这些控制的硬件。表面上看只是两个数组读口加一个算术 case，但完整项目有两个特殊要求：一拍可能提交两条指令；后面的指令可能在前面的指令写回之前就要读结果。

因此我们会先实现正确的单发射版本，再理解青龙为什么使用双 bank 和旁路。先区分两个问题：**寄存器堆存储已经提交的状态；旁路提供尚未写入或刚写入的较新结果。**

## 6.1 先写最简单的寄存器堆

在你自己的工程中，先建立一个最容易测试的版本：

```systemverilog
module regfile_one (
    input logic clk,
    input logic [4:0] rs1, rs2,
    output logic [31:0] r1, r2,
    input logic we,
    input logic [4:0] rd,
    input logic [31:0] wd
);
    logic [31:0] regs [0:31];
    assign r1 = rs1 == 0 ? 32'b0 : regs[rs1];
    assign r2 = rs2 == 0 ? 32'b0 : regs[rs2];
    always_ff @(posedge clk)
        if (we && rd != 0) regs[rd] <= wd;
endmodule
```

这段是本章为了说明结构给出的参考代码，不是仓库项目中的独立模块。`[0:31]` 有 32 个元素，其中第 0 项不依赖于存储值，因为读 x0 强制为零、写 x0 被丢弃。其他寄存器没有复位，只有真正写过才可用于确定值。

应自行写 testbench：在下降沿设置 `we=1,rd=3,wd=42`，下一个上升沿完成写；之后读 x3 应为 42。再尝试写 x0，读 x0 必须是 0。读未初始化的 x4 可能得到 X；不要把它当作失败，也不要假定硬件初值一定为零。

同一时钟沿读和写同一个寄存器时，仿真事件区、综合推断的存储器行为和流水线需求可能不同。项目不依赖猜测这种“读写同地址”行为，而是明确为 WB 写值加读口旁路。

## 6.2 当两条指令同时写回，为什么一个数组不够方便

双发射可能一拍写两个不同的 rd。直接写：

```systemverilog
if (we0) regs[rd0] <= data0;
if (we1) regs[rd1] <= data1;
```

功能上在明确冲突优先级后可以建模，但 FPGA 对两个独立写口的 RAM 推断不一定高效。项目使用两个**各有一个写口**的数组 [rv32_core.sv](../rtl/rv32_core.sv#L45-L49)：

```systemverilog
logic [31:0] regs_lane0 [0:31], regs_lane1 [0:31];
logic [31:0] regs_latest;
```

读某个寄存器时，`regs_latest[index]` 告诉我们哪个 bank 保存最新值。写第一退休口只写 bank 0、标记 latest=0；写第二退休口只写 bank 1、标记 latest=1：

```systemverilog
if (w_valid && w_write_rd && w_rd != 0) begin
    regs_lane0[w_rd] <= w_result; regs_latest[w_rd] <= 0;
end
if (w_second_valid && w_second_rd != 0) begin
    regs_lane1[w_second_rd] <= w_second_result; regs_latest[w_second_rd] <= 1;
end
```

看看三次写入 x7：

| 时刻 | 事件 | bank0[x7] | bank1[x7] | latest[x7] | 应读到 |
| --- | --- | --- | --- | --- | --- |
| 第一次写后 | 第一口写 10 | 10 | 未知 | 0 | 10 |
| 第二次写后 | 第二口写 20 | 10 | 20 | 1 | 20 |
| 第三次写后 | 第一口写 30 | 30 | 20 | 0 | 30 |

`latest` 仅在相应寄存器真正写入后才有意义。项目不复位这些 bank 和 latest；读尚未初始化的 x1～x31 不应依赖特定值。FPGA 资源映射还可能为多个异步读口复制 bank；双 bank 不是保证所有器件都恰好只用两块物理 RAM。

项目发射规则禁止同组 WAW；不要把第二个 always 赋值恰好排在后面当作架构冲突处理方案。后面双发射章会从年龄和配对约束推导这一点。

## 6.3 读口还要看到当前 WB 的新值

项目 [read_operand](../rtl/rv32_core.sv#L201-L208)：

```systemverilog
if (index == 0) read_operand = 0;
else if (w_second_valid && w_second_rd == index) read_operand = w_second_result;
else if (w_valid && w_write_rd && w_rd == index) read_operand = w_result;
else read_operand = regs_latest[index] ? regs_lane1[index] : regs_lane0[index];
```

这不是单纯的 RAM 读：如果当前 WB 正在写这个编号，直接返回 WB 数据；否则根据 latest 选择 bank。第二退休口代表同拍更年轻的指令，因此如果设计允许同地址重叠时逻辑优先选第二口；项目配对本身会禁止同组 WAW。x0 的判断放在最前面，任何旁路都不能改变 x0。

这解决的是 ID 读寄存器与当前 WB 的关系；指令进入 EX 后，仍可能需要 MEM/WB 的更多旁路，第 8 章详细推导。

## 6.4 自己写基础 ALU：每个操作的位宽要固定

一份便于理解的基础实现可以这样开始：

```systemverilog
always_comb begin
    result = 32'b0;
    case (op)
        ALU_ADD:  result = a + b;
        ALU_SUB:  result = a - b;
        ALU_SLL:  result = a << b[4:0];
        ALU_SRL:  result = a >> b[4:0];
        ALU_SRA:  result = $signed(a) >>> b[4:0];
        ALU_SLT:  result = {31'b0, $signed(a) < $signed(b)};
        ALU_SLTU: result = {31'b0, a < b};
        ALU_XOR:  result = a ^ b;
        ALU_OR:   result = a | b;
        ALU_AND:  result = a & b;
        ALU_COPY: result = b;
        default:  result = 0;
    endcase
end
```

这段是便于动手的等效思路，完整可综合模块还需要声明端口、导入 package，并测试实际工具；项目的移位硬件组织有所不同。

特别注意三件事：

1. 算术加减截断到 32 位：`0xffffffff + 2 = 1`，不会产生架构异常。
2. 比较有符号和无符号必须明确区分：`0xffffffff < 1` 在有符号数下为真（-1 < 1），无符号下为假。
3. RV32 的寄存器移位量只使用低 5 位：移位 33 相当于移位 1，不是全清零。算术右移必须让左操作数具备 signed 语义，否则高位填充可能错。

## 6.5 青龙的移位与旋转为什么共用部分逻辑

看 [rv32_alu.sv](../rtl/rv32_alu.sv#L9-L18)：

```systemverilog
wire rotating = EXTENSIONS && (op == ALU_ROL || op == ALU_ROR);
wire [31:0] shift_upper = rotating ? a : (op == ALU_SRA ? {32{a[31]}} : 32'b0);
wire [63:0] shifted_right = {shift_upper, a} >> b[4:0];
wire [63:0] shifted_left = {a, (rotating ? a : 32'b0)} << b[4:0];
```

右移时，若是算术右移，上半部填 32 个符号位；逻辑右移填 0；旋转右移在上半部再放一个 a。把 64 位拼接整体右移后，取低 32 位就实现相应结果。左旋转类似地把两个 a 拼起来左移，取高 32 位。

例如 `0x12345678` 右旋 8 位：最低字节 `78` 从右端出去后，从左端补回来，结果 `0x78123456`。如果移位量为 0，取到的仍是原值；实现循环移位时千万测试 0 和 31，避免表达式出现对 32 位数据移位 32 带来的边界错误。

## 6.6 Zba/Zbb 不是一个额外的“神秘运算块”

每个扩展指令最终仍是一种精确定义的位运算：

- `ANDN/ORN/XNOR`：先对部分输入取反再做逻辑运算。
- `MIN/MAX/MINU/MAXU`：先做对应有符号或无符号比较，再选择输入。
- `ROL/ROR`：循环移位。
- `CLZ/CTZ/CPOP`：分别统计前导零、末尾零、1 的数量。输入全 0 时 CLZ 和 CTZ 均为 32。
- `SEXTB/SEXTH/ZEXTH`：扩展字节或半字。
- `ORCB`：分别对每个字节做归约 OR，再把该结果扩成整个字节。
- `REV8`：交换 4 个字节的顺序。
- `SH1ADD/SH2ADD/SH3ADD`：先对 a 左移 1/2/3 位，再加 b。

项目 CLZ 使用分段判断 16、8、4、2、1 位；CTZ 将输入 bit 顺序反转后复用 CLZ。CPOP 用四位、八位、十六位的加法树，见 [19–41 行](../rtl/rv32_alu.sv#L19-L41)。这些组织有助于综合时控制路径深度；独立软件参考模型可以使用更直白的循环来计算期望值。

`EXTENSIONS=0` 的辅助 ALU 不实现这些扩展操作，输出默认 0；双发射配对逻辑必须保证扩展指令不会错误发到该辅助通道。只测 ALU 数学本身，不能证明配对控制也正确。

## 6.7 直接测项目 ALU

在项目根目录执行：

```powershell
iverilog -g2012 -s project_alu_tb -o "$env:TEMP\project_alu.vvp" `
  rtl/rv32_pkg.sv rtl/rv32_alu.sv tutorial/examples/05-project-alu/project_alu_tb.sv
if ($LASTEXITCODE -ne 0) { throw '编译失败' }
vvp "$env:TEMP\project_alu.vvp"
if ($LASTEXITCODE -ne 0) { throw '测试失败' }
```

[测试台](examples/05-project-alu/project_alu_tb.sv) 的 15 个手算用例包括负数比较、算术右移、移位量 33、旋转、零输入 CLZ/CTZ。预期 `PASS project_alu: 15 directed cases`。它已实际运行，仍不是完整覆盖。

要扩展成可信测试：对每种 op 随机取 a/b，用**独立算法**生成参考值；特别列出 `0、1、0x7fffffff、0x80000000、0xffffffff` 和移位量 `0、1、31、32、33`。对 CLZ/CTZ/CPOP 可以遍历每一个单比特输入及其反码，再检查大量随机数。
