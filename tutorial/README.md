# 从零写出青龙：一条从第一条指令走到完整项目的路

如果你第一次打开 [rv32_core.sv](../rtl/rv32_core.sv)，看到六百多行信号，不知道从哪一行写起，这是正常的。CPU 的难点不是记住几百个信号名，而是同时处理**多条年龄不同的指令**，并保证它们最终看上去仍像一条接一条执行。

这套教程围绕这个问题展开。前面先让一个小电路跑起来；之后我们会把它不断改造，并对照这个仓库真正使用的实现，直到你能解释和重建项目中的各个模块。**主体不是小玩具，而是项目 CPU 和 SoC 本身。**

## 从哪里开始

- 没写过 HDL，或者不知道 PC、指令和时钟是什么：从 [第 1 章](01-第一条指令.md) 开始，先跑通只支持 ADDI 的小 CPU。
- 能看懂基础 RTL，但不了解 RISC-V：不要跳过 [第 2 章](02-让程序真正跑起来.md)，亲手跟踪分支、循环、内存和机器码。
- 已经掌握单周期 CPU：快速读完前面两个实验，重点从 [第 4 章](04-完整项目从哪里开始.md) 起，逐个重建本仓库的真实模块。

建议按文件顺序阅读；在终端执行命令时，先确认当前目录，不要把示例文件写进项目的 `rtl/`。

## 第一部分：建立能看得见的直觉

1. [第一条指令：一个只会 ADDI 的 CPU](01-第一条指令.md)——时钟、PC、寄存器、立即数和自检。
2. [让一个求和程序跑起来](02-让程序真正跑起来.md)——算术、循环、分支、Load/Store 和跳转。
3. [内存不能立刻回答怎么办](03-让内存等待.md)——请求/响应握手、等待和字节写。

这里的 CPU 是故意限制功能的教学原型：它**不是完整 RV32I，也不是青龙**。它让我们看见后面真实设计要解决的问题，不用来充当项目成果。

教程将实现拆成可以逐步检查的中间目标。源码对照是为了让你理解**怎样写出同等行为**，不是把最终文件粘贴过去就宣布学会。由于最终项目包含大量为 PDS 和时序做的优化，第一次实现可以更保守；若要逐周期、资源和性能完全一致，还需要继续对照实际源码、工具版本和配置测试。

## 示例目录与验证说明

可运行示例在 [examples](examples/)；每个目录含自检 testbench，部分实验带教学源码，译码器等单元测试则直接引用仓库中的真实 RTL。它们使用 Icarus Verilog，不依赖修改项目的 Makefile。运行日志、合成结果和板上结果必须区分。

本次撰写时，阶段 1、阶段 2、等待 RAM、取指队列、多周期核心和简化流水核心示例，以及直接实例化项目译码器、ALU、CSR、除法器的定向测试均在 Icarus 编译并通过自检；Icarus 对部分 `always_comb` 常量位选择给出敏感度拓宽提示。另在 WSL 独立副本运行 `make lint`、`make check` 并成功退出：70 项上游 ISA 测试通过；lint 有警告，部分测试有明确跳过和覆盖边界。可选 DDR 协议和 SoC 仿真也在独立副本通过，见第 18 章。此次没有进行 FPGA 构建或上板测试，历史板测不能自动继承给当前源码。

赛题依据是 [紫光.pdf](../紫光.pdf) PDF 第 10–11 页。基础要求是 RV32I、至少三级流水线和基础外设；高阶要求包括两路组相联 I/D Cache、动态预测/异常中断和 AI 应用。当前默认项目没有 Cache 和完整 AI 应用，不能写成已实现；正式比赛通知有变动时以最新文件为准。
