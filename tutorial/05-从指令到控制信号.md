# 5. 写译码器：把 32 位指令变成后面各级能用的控制

我们现在开始写目标项目的第一个真实模块。你应该最终得到一个组合电路：输入 32 位 `insn`，输出一个描述该指令的 `decode_t`。它本身不读寄存器，也不进行加法；它只回答“这条指令需要哪些输入、将来可能做什么”。

学习本章时，请同时打开项目的 [rv32_pkg.sv](../rtl/rv32_pkg.sv) 和 [rv32_decode.sv](../rtl/rv32_decode.sv)。我们的目标不是记住 154 行源码，而是知道为什么每组字段存在、在哪里设置、哪里消费、写错时会表现成什么故障。

## 5.1 先选一条指令，看译码要交出什么

```asm
lw x5, 12(x1)
```

执行阶段需要：读 x1，和立即数 12 相加形成地址；发一个 Load；成功后把返回值写给 x5。因此译码结果至少需要：

```text
rs1=1             use_rs1=1
rd=5              reg_write=1
imm=12            src_imm=1
alu=ADD           load=1
funct3=010        决定这是 LW 而非 LB/LH/LBU/LHU
illegal=0
```

如果只是提取 `rs1=1` 和 `rd=5`，还不能正确控制硬件。因为有些指令同一位置的比特根本不是寄存器编号；例如 Store 的 `insn[11:7]` 是立即数一部分，不应该写寄存器。`use_rs1/use_rs2/reg_write` 就是对这些字段的使用资格说明。

## 5.2 第一个文件：定义控制字段

项目在 package 中定义运算编号和结构。先看 ALU 类型：

```systemverilog
typedef logic [4:0] alu_op_t;
localparam alu_op_t ALU_ADD=0, ALU_SUB=1, ALU_SLL=2, ALU_SLT=3,
    ALU_SLTU=4, ALU_XOR=5, ALU_SRL=6, ALU_SRA=7,
    ALU_OR=8, ALU_AND=9, ALU_COPY=10;
```

这些数字是硬件内部约定，**不是 RISC-V 的 opcode**。译码器和 ALU 使用同一个 package，避免译码器认为 3 是 SLT，ALU 却把 3 当成 XOR。项目没有用 `enum`，源码注释说明这是兼容特定版本 PDS ADS 前端的选择；功能上也可以用其他清晰、工具支持的编码方式。

实际 [decode_t](../rtl/rv32_pkg.sv#L13-L27) 包括：

```systemverilog
typedef struct packed {
    logic illegal;
    logic [4:0] rs1, rs2, rd;
    logic use_rs1, use_rs2, reg_write;
    logic [31:0] imm;
    alu_op_t alu;
    logic src_pc, src_imm;
    logic branch, jal, jalr;
    logic load, store;
    logic [2:0] funct3;
    logic mul, div;
    logic csr, csr_imm;
    logic [11:0] csr_addr;
    logic ecall, ebreak, mret, fence_i, serial;
} decode_t;
```

`packed` 让各字段成为一个固定宽度的位向量。数一数总宽度是 87 位：这也是项目译码器端口 `decoded[86:0]` 的宽度。项目用扁平端口而不是在端口上直接写带 package 名的 struct，是为了绕开特定 PDS 版本的兼容问题；模块内部依旧使用有名字的字段。

当你扩展结构时，要同时检查 package、译码器扁平端口和所有使用其位宽/布局的地方。位宽不匹配即使能编译，也可能造成字段被截断或错位。

## 5.3 每个字段是谁要用

下面按数据流解释，而不是要求你先把表背下来：

- `rs1/rs2/rd`：编号送到寄存器读口、依赖比较和未来写回。
- `use_rs1/use_rs2`：依赖逻辑判断该编号是否真的被读取；立即数字段与寄存器字段有重叠，不能只看数字。
- `reg_write`：指令成功时可能写 rd；异常时仍需后级抑制。
- `imm`、`src_pc/src_imm`：选择 ALU 的两个操作数；比如 AUIPC 的第一个输入是 PC、第二个是立即数。
- `load/store/funct3`：控制请求、字节宽度及加载结果扩展。
- `branch/jal/jalr`：计算真实下一 PC，并与预测比较。
- `mul/div`：启动/等待对应执行单元。
- `csr/csr_addr/csr_imm`：选择 CSR、数据来源和旧值写回。
- `serial`：指示必须处理与其他在途指令之间的顺序；`fence_i/mret` 还会影响前端。
- `illegal`：标识不接受的编码，后级把它变成非法指令异常，而不是继续执行正常副作用。

仔细看最后一点：`illegal=1` 并不保证这个 struct 里其他控制字段恰好都为零。后续 EX/MEM 必须以指令有效位和异常控制抑制副作用。不能把“译码器默认大多数位为 0”当成安全保障。

## 5.4 组合模块从默认值开始

项目 [rv32_decode.sv](../rtl/rv32_decode.sv#L10-L18) 的开头：

```systemverilog
always_comb begin
    op = insn[6:0]; f3 = insn[14:12]; f7 = insn[31:25];
    d = '0;
    d.rs1 = insn[19:15]; d.rs2 = insn[24:20]; d.rd = insn[11:7];
    d.funct3 = f3;
    d.alu = ALU_ADD;
    case (op)
```

`d='0` 先对整个结构赋默认值，避免不同 opcode 的分支遗留旧控制位。之后每种指令只修改需要的字段；未识别 opcode 最终将 `d.illegal=1`。

一种常见错误是把 `d` 赋值放进某几个 case，却忘了其他分支：当输入改变时，输出需要保留旧值，综合器可能推断锁存器。组合译码不应该依赖上一条指令留下的状态。

## 5.5 实现五种立即数

将下列表达式抄到自己的笔记，并用正数与负数各算一次：

```systemverilog
imm_i = {{20{insn[31]}}, insn[31:20]};
imm_s = {{20{insn[31]}}, insn[31:25], insn[11:7]};
imm_b = {{19{insn[31]}}, insn[31], insn[7],
         insn[30:25], insn[11:8], 1'b0};
imm_u = {insn[31:12], 12'b0};
imm_j = {{11{insn[31]}}, insn[31], insn[19:12],
         insn[20], insn[30:21], 1'b0};
```

对于 B 型，拼出的原始偏移是 13 位：最高位 `insn[31]` 是符号位，最低位强制为 0，前面的 19 个符号位将它扩展到 32 位。J 型原始偏移是 21 位，前面复制 11 次符号位。U 型不是普通符号扩展，而是将指令高 20 位放进结果高 20 位，低 12 位填零。

练习 `beq x1,x2,+8`：编码是 `0x00208463`，将 `insn[11:8]=4` 放进 `imm[4:1]`，最低位补 0 得到 8。再看第 2 章的 `bne x2,x0,loop`，其偏移为 -8，重组后应是 `0xfffffff8`。如果你只是顺序取 `insn[31:20]`，两个例子都会错。

## 5.6 逐组补全基本指令

你自己的译码器建议按以下顺序增加，每完成一组就先写对应测试。

### LUI 与 AUIPC：相同立即数，不同的第一个操作数

源码 [19–24 行](../rtl/rv32_decode.sv#L19-L24) 同时处理两者：两者写 rd，立即数都是 U 型。LUI 选择 `ALU_COPY`，把立即数作为结果；AUIPC 选择 `ALU_ADD`、`src_pc=1`，将该指令的 PC 与立即数相加。

这时就要明确 `src_pc` 用的是**这条指令携带的 PC**，不是已经前进的取指 PC。译码器只给出选择，流水线必须把正确 PC 带到 EX。

### JAL 与 JALR：数据结果和 PC 结果是两回事

JAL 写入的 rd 结果是 PC+4，目标是 PC+J 型偏移；JALR 读取 rs1，目标是 `(rs1+imm_i)&~1`，`funct3` 必须是 0。译码器分别置 `jal/jalr`，后续 EX 根据类型决定目标和写回结果。

无 C 扩展时，目标 bit 1 仍须检查：清 bit 0 不是保证四字节对齐。对齐失败时不应把链接地址作为正常写回提交。

### 分支：比较两个源寄存器，不写 rd

[分支译码](../rtl/rv32_decode.sv#L35-L40) 设置 `branch`、两个 `use_rs` 和 B 型立即数，并禁止保留的 funct3 2/3。EX 再根据 funct3 选择相等、有符号/无符号大小比较。

分支的 `insn[11:7]` 是立即数片段，因此即使这些位恰好等于某个非零数字，`reg_write` 也必须是 0。

### Load/Store：宽度需要一路带到响应处理

Load 设置 `load=1`、`reg_write=1`、`use_rs1=1`、I 型偏移。Store 设置 `store=1`、两个 `use_rs`、S 型偏移，但不写 rd。项目用 `funct3` 表示字节、半字、字及扩展方式，并拒绝该实现未定义的宽度。

只要将 `load=1` 带到 MEM 还不够：后面要根据 `funct3` 和原始地址低位，判断使用哪个 byte lane，以及 LB/LH 是符号扩展还是 LBU/LHU 的零扩展。

### 寄存器与立即数算术

opcode `0x13` 是立即数算术组，`0x33` 是寄存器算术组。两者常用同一种 ALU 操作，但寄存器组读取 rs2，立即数组选择 `imm`。对 ADD/SUB 和移位等，还必须检查 `funct7` 或相应高位，不能只看 `funct3`。

项目先处理常规算术，然后对 Zba/Zbb 特定编码作明确覆盖。请逐个对照 [51–127 行](../rtl/rv32_decode.sv#L51-L127) 和正式规范；不要只把一条 ADD 改成“凡是不认识都默认 ADD”。

## 5.7 M 扩展如何走出普通 ALU 路径

当寄存器算术组的 `funct7=1`，项目用 `funct3[2]` 区分乘法与除法，设置 `mul/div`。这些位告诉核心选择不同执行/等待逻辑，而不是让基础 ALU 在单周期组合地做所有运算。

注意：本处的 `funct3` 还必须留给后续单元，区分 MUL/MULH/MULHSU/MULHU、DIV/DIVU/REM/REMU。把译码结果压缩成一个“是乘除”标志，会丢掉操作和有符号信息。

## 5.8 系统指令与串行标志

[129–150 行](../rtl/rv32_decode.sv#L129-L150) 处理屏障和系统指令。`FENCE`、`FENCE.I`、CSR、ECALL、EBREAK 和 MRET 都需要明确排序及异常行为；项目将这些操作标记 `serial`，在发射前后阻止不适当的重叠。

对于 CSR 寄存器形式，`rs1` 指向寄存器；立即数形式 `insn[19:15]` 是 zimm，不应读取寄存器，所以项目设置：

```systemverilog
d.csr_imm = f3[2];
d.use_rs1 = !f3[2];
```

真正读写 CSR 时，`CSRRS/CSRRC` 的零源与写只读寄存器的规则还要在执行/CSR 逻辑中判断；仅靠 `d.csr=1` 不能保证合法。WFI 在本项目中被当作合法的串行空操作，不代表已实现休眠电源管理。

## 5.9 现在用独立 testbench 验证项目译码器

教程带了 [project_decode_tb.sv](examples/04-project-decode/project_decode_tb.sv)，它直接实例化仓库真实的 package 和译码器，而不是另写一个差不多的译码器。**从项目根目录**运行：

```powershell
Set-Location D:\FPGA\RiscV
iverilog -g2012 -s project_decode_tb -o "$env:TEMP\project_decode.vvp" `
  rtl/rv32_pkg.sv rtl/rv32_decode.sv tutorial/examples/04-project-decode/project_decode_tb.sv
if ($LASTEXITCODE -ne 0) { throw '编译失败' }
vvp "$env:TEMP\project_decode.vvp"
if ($LASTEXITCODE -ne 0) { throw '测试失败' }
```

预期 `PASS project_decode: 7 directed cases`。测试检查 ADDI 负立即数、SW 的两个源、BEQ 偏移、SUB、MUL、CSRRW 以及未知 opcode。这个测试已在本机 Icarus 运行；会出现敏感度拓宽提示，退出码和 PASS 仍需同时核对。

七个例子当然远远不够。接下来你应增加：

1. 每种支持指令的合法编码和边界值。
2. funct3/funct7 中应拒绝的组合；对扩展覆盖的位置尤其仔细。
3. I/S/B/J 的最大正数、最小负数和 0。
4. 对立即数形式检查 `use_rs2=0`；对 Store 检查 `reg_write=0`。
5. `rd=x0` 的合法指令仍可正常执行，但后级不应改变 x0。
6. 同一个译码器连续输入不同类型，检查上条的控制位没有残留。

修改你自己的译码器后，逐一将结果和正式规范、仓库实现比较；若二者有差异先判断是实现 bug、扩展配置差异还是规范版本差异，不要先改期望使测试通过。

## 5.10 这一模块完成后你应该能回答

拿到一条 `sw x5,8(x1)`，你能不用猜地给出 `use_rs1/use_rs2/reg_write/imm/store/funct3`，解释每个字段被哪个后级使用；把它与前后的 ADDI 放在一起时，也知道为什么必须依赖 `use_rs*` 而不是无条件比较指令中的位。
