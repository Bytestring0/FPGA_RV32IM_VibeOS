# 10. 从单发射到双发射：并行执行，按程序顺序交账

假设程序连续有两条指令：

```asm
addi x1,x0,1
addi x2,x0,2
```

它们互不依赖，完全可以同一拍开始计算。双发射想获得的就是这样的并行性。但换成：

```asm
addi x1,x0,1
addi x2,x1,2
```

第二条需要第一条的结果。如果两个 ALU 都在同一拍使用旧寄存器值计算，第二条会错。即便两条不依赖，还要考虑跳转、异常、访存和两条同时写同一寄存器。

因此本章要解决的不是“放两个 ALU 就行”，而是：**如何安全选出一对指令，怎么安排物理执行通道，最后怎么按程序年龄提交。**源码主要看 [元数据与依赖](../rtl/rv32_core.sv#L63-L82)、[配对](../rtl/rv32_core.sv#L327-L355)、[流水寄存器和退休排序](../rtl/rv32_core.sv#L579-L645)。

## 10.1 先定义年龄，不要先叫 lane0/lane1

程序顺序中的先后称为年龄：

```text
A：PC=P       较老
B：PC=P+4     较年轻
```

这个项目只对队首两条连续指令考虑成对发射，检查 `fetch_pc[1] == fetch_pc[0]+4`。程序年龄与物理 ALU 编号是不同概念：项目有时把较年轻的 B 送到功能完整的主通道，把较老的 A 送到简单辅助通道。以后论证异常和提交时，一定先写 A/B，最后再标物理通道。

## 10.2 两条指令在发射前需要检查什么

逐项想一想：

1. 两项真的都有效且 PC 相邻吗？取指错误是否存在？
2. 预测路径是否允许把它们看成连续执行？
3. 两者的类型是否能分别放到主/辅助通道？
4. 年轻指令是否读取年长指令即将写的 rd（RAW）？
5. 两者是否写同一个非零 rd（WAW）？
6. 系统指令、屏障和特殊控制流是否要求独占或串行？

如果任何条件不满足，不是把指令丢掉，而是只发射较老的 A；B 留在队列，下一次继续考虑。项目采用保守禁止同组 RAW/WAW，而不是在同组中把第一个 ALU 的结果组合旁路给第二个 ALU。

## 10.3 手算 RAW 与 WAW

设译码得到 A 的 `rd/write` 和 B 的 `rs1/rs2/use`，概念检查为：

```text
A 写 rd 且 rd != 0，并且：
  B 真正读 rs1 且 B.rs1 == A.rd   → RAW
  B 真正读 rs2 且 B.rs2 == A.rd   → RAW
  B 也写同一个 rd                → WAW
```

例子：

```asm
addi x5,x0,7
add  x6,x5,x2       # RAW：B 读 A 的 x5，不能同组

addi x5,x0,7
addi x5,x0,9        # WAW：两者都写 x5，不能同组

addi x0,x0,7
addi x6,x0,9        # 写 x0 被忽略，不制造真实依赖
```

另一个容易误判的情况：`addi x6,x2,5` 中物理 `insn[24:20]` 是立即数片段，不是 B 真正读取的 rs2。只有 `use_rs2=1` 才用它判断 RAW。项目 [pair_dependency](../rtl/rv32_core.sv#L79-L82) 恰好根据预译码的使用位和目的写位检查这些关系。

WAR（A 读、B 写同一寄存器）在这一组中不必像 RAW 那样一律禁止：两个操作数都代表发射时 A/B 应看到的旧值，较年轻 B 的写回更晚发生。不过实现上仍要确保读口、旁路和退休时序确实保持该语义；不要仅凭名字推断任何流水线都安全。

## 10.4 辅助通道为什么只能做简单指令

项目的 lane0 是完整通道：访存、分支、乘除、系统操作与扩展等在这里处理；lane1 是第二个简单整数 ALU，实例化时 `EXTENSIONS=0`。预译码 `issue_metadata` 中的最高位表示一条指令是否适合辅助通道，大致要求：

```text
合法、非 serial、会写寄存器、ALU 是基础操作，且不是访存/乘除/分支跳转
```

这不仅是减少硬件：它也简化了同组中的异常和副作用情况。若把 Load 错误地送到只会做 ALU 的辅助通道，结果就不是“慢一点”，而是根本没有执行内存访问。

## 10.5 第一种情况：正常配对

```text
A → 完整通道
B → 辅助通道
```

例如：

```asm
lw   x5,0(x1)      # A 需要完整通道
addi x6,x2,1       # B 可在辅助通道，且不依赖 A
```

当前实现 [pair_normal](../rtl/rv32_core.sv#L329-L333) 还要求 A/B 无取指错误、A 非非法/串行/控制流、B 符合简单通道条件、预测 PC 顺序，并排除 A 与 B 的依赖。两条进入同一 EX 组后，B 的结果与 A 同步经过后级；如果 A 的 Load 在 MEM 等待，B 也不能提前作为更年轻指令退休。

指令类型允许配对，不代表每次一定会双发：队列中需要有两项、后端须 ready、不能存在其他阻塞。验证吞吐时要确认确实触发了双发/双退休，而不是只检查最终值。

## 10.6 第二种情况：动态交换物理通道

再看：

```asm
addi x6,x2,1      # A 简单、较老
lw   x5,0(x1)     # B 较年轻，需要完整通道
```

若只允许正常顺序，B 无法放到辅助 ALU，只能分两次发。项目可交换：

```text
A → 辅助通道（物理 second，但程序更老）
B → 完整通道（物理 main，但程序更年轻）
```

它要求 A 可由简单辅助 ALU 完成，B 非非法/串行、两者没有同组依赖，并要求第一条预测为顺序。具体约束见 [pair_swap_candidate](../rtl/rv32_core.sv#L334-L345)；候选与实际发射还需 `id_issue`。`x_swapped` 和 `m_swapped` 跟随这组指令，记录物理位置与程序年龄相反。

注意这不是乱序发射：两条仍然作为程序相邻的一个组按序进入，允许的物理功能单元不同；退休时必须恢复程序顺序。

## 10.7 EX 寄存器怎么保存一对指令

看 [579–599 行](../rtl/rv32_core.sv#L579-L599)。当允许发射时：

- 非交换：`x_dec/x_pc/x_insn` 保存 A，`x_dec_second/...` 保存 B。
- 交换：`x_dec/x_pc/x_insn` 保存 B，`x_dec_second/...` 保存 A，`x_swapped=1`。
- 若只能发一条，`x_second_valid=0`，辅助通道中的旧数据不应造成任何副作用。

你自己写时可以先使用两个完整的结构体保存 PC、指令、控制、操作数，再增加 `older_is_aux` 标记。只有行为正确后再像项目一样减少字段或提前计算比较，便于定位错误。

两条的操作数都需要考虑来自更老 MEM/WB 两个通道的旁路。不要只复制主通道的 `a/b`，忘了辅助通道自身的 rs1/rs2；项目用四组匹配位对应两通道四个源操作数。

## 10.8 最难的例子：年轻 Load 错误，老 ADDI 怎么办

延续交换配对：

```asm
A: addi x6,x2,1
B: lw   x5,0(x1)    # 访问出错
```

如果 B 发生数据访问异常，按顺序执行的架构语义是：A 在 B 之前，A 的结果应该保留；B 不正常写 x5；B 之后的所有指令不得提交。陷阱 PC 是 B 的 PC，不是物理辅助通道的 PC。

项目在 MEM→WB 的两个 valid 处理：

```systemverilog
w_valid <= m_finish && (!mem_trap || (m_swapped && m_second_valid));
w_second_valid <= m_finish && !mem_trap && m_second_valid;
```

`m_swapped && m_second_valid` 表示物理辅助通道是较老 A。即使完整通道的年轻 B 触发 `mem_trap`，第一退休口仍可输出 A；第二退休口不能正常退休出错的 B。接下来 WB 选择 PC、insn、rd 和 result 时也根据 `m_swapped` 恢复程序顺序。

这段不能简单移植到另一种通道/异常模型中：成立的前提包括辅助指令类型受到限制、其他更老故障被禁止，以及控制与时钟沿优先级一致。自己先从顺序语义写独立参考，再对照项目。

## 10.9 相反：较老指令出错，年轻指令必须失效

正常配对下：

```asm
A: lw   x5,0(x1)    # 较老，访问错误
B: addi x6,x2,1     # 较年轻
```

A 报错时 B 虽已算出一个值，也不能提交。它的执行结果是投机性的，必须丢弃。项目 `w_second_valid` 包含 `!mem_trap`，故 B 不正常退休。

再看 EX 本地异常：

```systemverilog
m_second_valid <= x_go && x_second_valid &&
    (!x_exception || x_swapped) && !mem_trap && !irq_take;
```

未交换时完整通道是老 A，A 的本地异常应禁止较年轻辅助指令。交换时完整通道是年轻 B，辅助通道是老 A，所以本地异常不能自动丢掉老 A。真正能否退休还要继续受 MEM 的异常判断控制。

## 10.10 退休接口必须恢复年龄顺序

项目 WB [635–644 行](../rtl/rv32_core.sv#L635-L644) 根据 `m_swapped` 选择数据：

```text
非交换：第一退休 = main(A)，第二退休 = auxiliary(B)
交换：  第一退休 = auxiliary(A)，第二退休 = main(B)
```

第一退休 PC 在交换时从 main PC 减 4，第二退休 PC 是第一 PC+4；这一推导依赖配对时已确认两条地址相邻。参考模型必须先执行第一退休，再执行第二退休，不能按物理 ALU 编号更新架构状态。项目的 [差分模型](../sim/core_main.cpp#L175-L187) 就是这样处理的。

## 10.11 从一个能运行的单发射版本逐步实现

1. 让取指队列能保存两条，但 `fetch_pop` 固定最多 1；确认回归与无队列单发射一致。
2. 添加第二个基础 ALU，先只允许两条独立的简单算术指令同组。
3. 记录一对指令各自的 PC/insn/rd/result，按年龄给出两个退休口。
4. 对同组 RAW/WAW、x0、连续 PC 与错误位做拒绝测试；统计确有双退休发生。
5. 允许完整通道处理更广的第一条，同时简单指令作为第二条；验证 MEM 等待时两者作为一组保持。
6. 添加动态交换和 `swapped` 标记，先测正常结果，再测年轻异常保留老结果。
7. 最后加入预测、中断、CSR、乘除与访存组合，复跑单发射和双发射差分。

不要把这个顺序理解为可以省略较早的异常设计：若第一次只做无异常的双发射，一旦引入 Store 或错误响应，就必须重新设计门控和退休，直到年龄语义成立。

## 10.12 最小回归表

| 测试 | 要观察什么 |
| --- | --- |
| 两条独立 ADDI | 真的同组且两条按顺序退休 |
| A 写 x5、B 读 x5 | 不同组，B 读到新值 |
| A/B 都写 x5 | 不同组，最终 x5 是 B 的值 |
| A 写 x0、B 读 x0 | 不产生假的 RAW，读到 0 |
| A Load、B 独立 ADDI | Load 等待时 B 不提前退休 |
| A 简单 ALU、B Load | 检查确实发生交换 |
| 上例 B 总线错误 | A 退休、B 陷阱、B 不写 rd |
| A Load 错误、B 简单 ALU | B 不退休 |
| 分支预测错误后年轻 Store | 错误路径设备写次数为 0 |
