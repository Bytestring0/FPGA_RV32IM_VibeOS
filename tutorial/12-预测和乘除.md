# 12. 写预测器和乘除：让正确的核心跑得更快

到现在为止，我们已经能解释一个保守的顺序 CPU。剩下两个重要问题：

- 分支真正算出来之前，前端要不要停？
- 乘法和除法怎么实现，等待过程中流水线如何保持一致？

这两类功能表面无关，却有一个共同原则：**性能机制不能改变程序的架构结果**。预测错了要修正；多周期运算未完成时不能让消费者用到错误数据。

## 12.1 为什么先关闭预测验证 CPU

分支 `beq x1,x2,target` 在读到操作数、比较后才知道下一 PC。最简单的实现可以暂停前端，等结果出现再取指，结果正确但有空泡。也可以先假定顺序执行 `PC+4`，如果分支实际跳转，再丢弃错误路径并从目标重新取指。

项目把默认顺序取指扩展为动态预测。无论预测器输出什么，EX 都计算真实结果：

```systemverilog
actual_next = taken ? branch_target : x_pc + 32'd4;
```

再与这条指令携带的 `x_pred` 对比，不同就重定向。关闭预测与启用预测，允许周期数不同；同一个确定性程序的正常退休流、内存与陷阱行为必须一致。

## 12.2 BTB 在解决什么

BTB 可以理解为“这个 PC 上次发生控制流转移时，目标大概在哪里”的表。项目 [rv32_predictor.sv](../rtl/rv32_predictor.sv) 按 PC 某些位选择项：

```systemverilog
ri = pc[INDEX_BITS+1:2];
```

该索引丢弃低两位，因为指令按 4 字节对齐。很多不同 PC 仍可能映射到同一索引，所以每项保存 tag；只有 `valid` 且 tag 匹配，才能把这项当作当前 PC 的预测。

未命中默认 `next_pc=pc+4`。命中且方向决定预测跳转时，取保存的目标，或者在返回指令/RAS 有值时取返回栈顶。`pc_second` 对应第二个可能连续的指令，也独立输出一个预测；实际是否接收第二条由前端判断。

## 12.3 两位饱和计数器怎样避免一次反常就翻转预测

对于条件分支，项目可以根据局部历史选择一个两位计数器，其基本行为是：

```text
00 强不跳  ←→ 01 弱不跳  ←→ 10 弱跳  ←→ 11 强跳
              实际跳转：向右加一（到 11 饱和）
              实际不跳：向左减一（到 00 饱和）
```

最高位为 1 表示预测跳转。如果循环连续跳转，计数器逐渐偏向跳转；循环结束时一次不跳不会立刻抹掉过去的趋势。它只是预测，不保证每次正确。

默认实现包含每项局部历史，并使用历史值选择不同的方向计数 bank。项目 [35–50 行](../rtl/rv32_predictor.sv#L35-L50) 每个 bank 独立单写，有利于目标工具推断 LUT RAM；历史与 tag 不匹配时初始化对应状态。不要把它描述成“只有一张全局二位计数器表”。

## 12.4 函数返回为什么需要 RAS

同一条 `ret` 指令可能从不同调用位置进入函数，固定 BTB 目标不一定正确。返回地址栈（RAS）记录调用指令的 `PC+4`，预测返回时取栈顶。

项目有 16 项栈和计数：执行到识别的调用时 push，执行到识别的返回时 pop；它根据已经执行的事件更新，而不是在取指阶段投机修改，因此不需要对投机栈执行回滚。代价是短调用/返回链有时预测不及时；EX 的真实下一 PC 比较仍会纠正。

项目识别调用/返回的具体寄存器条件在 [train 信号](../rtl/rv32_core.sv#L184-L197)：调用写 x1/x5；返回为符合条件的 JALR 等。预测器是微架构启发式，不改变 JAL/JALR 的 ISA 语义。

## 12.5 错误预测如何清理

一条分支到 EX 后，必须使用它保存的预测值，不是前端当前对其他 PC 的预测：

```systemverilog
x_redirect = x_go && !x_exception &&
             ((taken ? branch_target != x_pred : (x_pc + 32'd4) != x_pred) ||
              x_dec.fence_i || x_dec.mret);
```

若不一致：队列中更年轻的错误路径清除；已被接受但未返回的旧路径取指标记 killed；从真实目标重新取指。更老的指令继续完成。`FENCE.I/MRET` 也会触发相关重定向处理；`FENCE.I` 清理预测状态的具体信号在预测器实例附近。

实现时先测试“不管预测如何，退休流都正确”，再统计命中率。故意让一个分支长期走反方向，检查错误路径上的 Store 没有发出；把预测开关关掉再次运行相同测试。

## 12.6 乘法的四种结果

RV32M 乘法的低 32 位和高 32 位需求不同：

```text
MUL    a*b 的低 32 位
MULH   signed(a)*signed(b) 的高 32 位
MULHSU signed(a)*unsigned(b) 的高 32 位
MULHU  unsigned(a)*unsigned(b) 的高 32 位
```

低 32 位按模 2³² 运算，signed/unsigned 对结果低半没有区别；高半则必须正确处理符号扩展。项目先把操作数扩成 33 位 signed：

```systemverilog
mul_a = $signed({((funct3 == 1 || funct3 == 2) && a[31]), a});
mul_b = $signed({(funct3 == 1 && b[31]), b});
```

这使 MULH 两端有符号、MULHSU 只有 a 有符号、MULHU 两端视作非负。随后 [核心 100–120 行](../rtl/rv32_core.sv#L100-L120) 将运算拆为低/高片的部分积，减少目标 FPGA 上长 DSP 级联路径；高位结果可按 `MULH_PIPELINE` 增加一级。你可以先写一个容易核对的 64 位参考乘法，再对拆分实现逐项比对；不要在硬件和参考中复制同一段拆分逻辑，否则两边可能犯同一错误。

## 12.7 除法先把数学角落列出来

RISC-V 32 位除法与余数要求：

| 情况 | 商 | 余数 |
| --- | --- | --- |
| 普通 signed | 向零截断 | 余数符号跟被除数 |
| 除数为 0 | `0xffffffff` | 原被除数 |
| `0x80000000 / 0xffffffff`（有符号溢出） | `0x80000000` | 0 |
| unsigned | 无符号除法 | 无符号余数 |

例如 `-7 / 3 = -2`，`-7 % 3 = -1`，不是向负无穷取整的 -3。C/C++ 参考模型对 INT_MIN/-1 等情况也要显式处理，避免语言级未定义行为。

## 12.8 一位一位做除法，而不是组合 `/`

项目 [rv32_divider.sv](../rtl/rv32_divider.sv) 使用 radix-2 restoring division。对无符号正数，可以先用十进制直觉理解：从被除数的高位逐步移入余数，尝试减去除数；如果够减，保留差并在商中写 1，否则保留原余数并写 0。32 位输入要重复 32 次。

代码关键组合部分：

```systemverilog
trial = {remainder[31:0], quotient[31]};
difference = trial - {1'b0, divisor};
q_next = {quotient[30:0], !difference[32]};
r_next = difference[32] ? trial[31:0] : difference[31:0];
```

`trial` 多出一位，减法最高位帮助判断借位；商寄存器一边左移一边接收本轮的商位。对有符号输入，模块先保存符号、必要时准备绝对值；迭代后按记录对商和余数恢复符号。除 0 和有符号溢出按 ISA 特殊结果处理，不能沿用软件语言异常行为。

## 12.9 多周期单元如何接入 EX

除法器接口有 `start/busy/done/cancel/result`。`start` 只能对空闲操作发一次；EX 中的除法必须保持，直到 `done` 或已保存的结果可用。项目使用 `div_started` 防止重复启动；如果 `done` 出现时 EX 仍因下游暂停，保存 `div_saved_result`，防止一拍脉冲消失后丢失结果。

更老的 MEM trap 或中断进入时，年轻的除法不应继续影响架构；项目把 `mem_trap || irq_take` 送给 divider 的 `cancel` 并清理相关状态。测试必须覆盖“除法已经进行多拍，突然被取消”与“done 与下游 stall 重叠”。

在项目根目录运行：

```powershell
iverilog -g2012 -s project_divider_tb -o "$env:TEMP\project_divider.vvp" `
  rtl/rv32_divider.sv tutorial/examples/07-project-divider/project_divider_tb.sv

```

[测试台](examples/07-project-divider/project_divider_tb.sv) 检查 signed/unsigned 商余数、除零、溢出、取消与取消后的新事务，预期 `PASS project_divider: 9 cases and cancel`。这不覆盖所有 2⁶⁴ 组操作数，也不证明 EX 连接正确；还要增加随机参考对比、长时间 stall 和异常交互。

## 12.11 这些优化完成后如何确认没有改坏系统

1. 无预测、单发射、保守 Load 等待：运行架构回归，保存退休流和周期数。
2. 只开启预测：比较退休流与内存，检查错误预测计数；周期允许变化。
3. 只改变旁路/早发参数：特别测试紧邻 Load 的消费者及背压稳定。
4. 开启双发射：按两个退休口的程序顺序比较，不只比较最终寄存器。
5. 改变乘法高位流水参数：乘法消费者紧随、交错其他指令、异常与等待均需覆盖。

项目参数与回归命令在 [第 14 章](14-验证与调试.md)。先把核心接成完整系统：[第 13 章](13-SoC与固件.md)。
