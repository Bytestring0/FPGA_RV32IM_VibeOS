# 9. 写访存路径：让一条 Load 或 Store 不重不漏地完成

我们要实现的不是“计算地址然后读数组”这么简单。以 `lb x5,3(x1)` 为例，CPU 要完成：

1. 从最新的 x1 和符号扩展立即数计算**字节地址**。
2. 检查该宽度的地址对齐和指令合法性。
3. 把地址变成总线要求的对齐字地址，发出且只发出一次请求。
4. 等待响应，记住它属于哪条指令、哪一个目的寄存器。
5. 从 32 位响应中选取地址对应字节，按 LB 要求符号扩展。
6. 如果发生错误，报告异常，禁止错误的寄存器写回与年轻副作用。

本章的目标是沿这个顺序把项目 [EX 请求逻辑](../rtl/rv32_core.sv#L402-L430)、[MEM 响应逻辑](../rtl/rv32_core.sv#L381-L400) 与状态更新连起来。

## 9.1 算地址：立即数已经在译码阶段准备好了

Load 使用 I 型立即数，Store 使用 S 型立即数，但到 EX 时都已经放在 `x_dec.imm`：

```systemverilog
wire [31:0] memory_address = a + x_dec.imm;
```

这里 `a` 不是简单的寄存器数组输出，而是经过最新值旁路后的 rs1。Store 的待写入数据也是经过旁路的 `b`；因此 `addi x2,...; sw x2,0(x1)` 不只依赖地址，还依赖 Store 数据。

假设 x1=`0x1001`、偏移是 -1，则有效地址是 `0x1000`。所有计算是 32 位，负数立即数已经符号扩展，不能在加法时再把它当无符号 12 位数。

## 9.2 对齐检查发生在发请求之前

项目不拆分跨字访问。按访问大小：

| 访问 | 必须满足 | 例子 |
| --- | --- | --- |
| byte | 任意低两位 | `LB 0x1003` 合法 |
| halfword | bit 0 为 0 | `LH 0x1002` 合法，`LH 0x1001` 不对齐 |
| word | 低两位全 0 | `LW 0x1000` 合法，`LW 0x1002` 不对齐 |

代码：

```systemverilog
wire memory_misaligned =
    (x_dec.funct3[1:0] == 1 && memory_address[0]) ||
    (x_dec.funct3[1:0] == 2 && memory_address[1:0] != 0);
```

它依赖译码器已经拒绝不合法的宽度编码。非法指令不能因为低两位恰好表示 byte 就发出请求。Load 不对齐 cause 是 4，Store/AMO 不对齐 cause 是 6，`mtval` 使用原始有效地址。精确的异常优先顺序见第 11 章。

对齐检测不是“总线返回错误以后再处理”：项目在 EX 阶段发现不对齐时就禁止 `d_req_valid`，因此对应 Store 不会落到外设。

## 9.3 为什么把总线地址低两位清零

数据总线一次访问一个 32 位对齐字：

```systemverilog
d_req_addr = {memory_address[31:2], 2'b0};
```

例如字节地址为 `0x1003`，总线地址是 `0x1000`。但这不意味着低两位可以丢掉：对 Load，需要在响应后知道取第 3 个字节；对 Store，需要选第 3 个写使能和把字节数据移到对应位置。项目将原始地址保存为 `m_addr`。

如果错误报告时只保存总线对齐地址，`mtval` 会从 `0x1003` 错误地变成 `0x1000`。因此“总线地址”与“架构有效地址”必须是两个概念。

## 9.4 Store：数据和字节使能一起移动

项目 EARLY_LSU 模式下：

```systemverilog
d_req_wdata = x_dec.store ? b << {memory_address[1:0], 3'b0} : 32'b0;
case (x_dec.funct3[1:0])
    0: d_req_wstrb = 4'b0001 << memory_address[1:0];
    1: d_req_wstrb = 4'b0011 << memory_address[1:0];
    default: d_req_wstrb = 4'b1111;
endcase
```

`{memory_address[1:0],3'b0}` 等于地址低两位乘 8：每前进一个字节，数据在 32 位总线上左移 8 位。例子：

```text
SB，地址 0x1002，rs2=0xaabbccdd
对齐地址  = 0x1000
wdata     = 0x00dd0000   （32 位左移后高位截断）
wstrb     = 0100
```

只有低字节 `dd` 会写到地址 `0x1002`。半字地址 `0x1002` 对应 `wstrb=1100`；地址 `0x1001` 虽能算出位选通，也必须因不对齐禁止请求。字写只能地址低两位为 0，使用 `1111`。

检查测试时记得分别断言 `addr/wdata/wstrb/write`。只检查最终内存值，可能掩盖一次错误额外写之后又被覆盖的问题；尤其在 MMIO 上，额外一次写可能不可逆。

## 9.5 Load：选择 lane 后再扩展

响应带回对齐地址的完整 32 位字，项目在 MEM 用原始低两位右移：

```systemverilog
load_shifted = d_rsp_data >> {m_addr[1:0], 3'b0};
case (m_funct3)
    0: mem_result = {{24{load_shifted[7]}},  load_shifted[7:0]};
    1: mem_result = {{16{load_shifted[15]}}, load_shifted[15:0]};
    4: mem_result = {24'b0, load_shifted[7:0]};
    5: mem_result = {16'b0, load_shifted[15:0]};
    default: mem_result = d_rsp_data;
endcase
```

例子：`d_rsp_data=0x80aa1122`，有效地址偏移为 3：

```text
load_shifted = 0x00000080
LB  结果 = 0xffffff80  （符号扩展，十进制 -128）
LBU 结果 = 0x00000080  （零扩展，十进制 128）
```

LW 只有在原始地址字对齐时才发请求，所以直接使用完整响应。必须让 `m_funct3` 和 `m_addr` 属于同一条 Load，不能使用此时 EX 里另一条指令的控制。

## 9.6 何时发请求：完整门控才安全

项目默认 `EARLY_LSU=1`，在 EX 阶段尝试发起访存：

```systemverilog
d_req_valid = x_valid && (x_dec.load || x_dec.store) &&
    !x_error && !x_dec.illegal && !memory_misaligned &&
    !hazard && m_ready && !mem_trap && !irq_take && !rst;
```

不要只背公式，逐条问“去掉它会怎样”：

- `x_valid`：泡沫里的旧控制不能造成访问。
- `load || store`：普通 ALU 不能访问总线。
- `!x_error && !illegal`：取指错误或非法指令不得作为有效访存执行。
- `!memory_misaligned`：不对齐请求在本地变为异常。
- `!hazard`：基址或写数据尚未可用时不能发。
- `m_ready`：后级无法接收该指令时，不能只让请求独自走掉。
- `!mem_trap`：较老 MEM 指令在同拍发现异常时，禁止较年轻 Store 出现在总线上。
- `!irq_take && !rst`：中断进入/复位相关条件下不启动请求。

具体门控和项目流水推进、早发请求协同设计；移植时若改了状态机，必须重新证明“请求被接收”和“对应指令进入等待状态”始终一一对应。

## 9.7 请求只接受一次，响应只消费一次

`d_accept = d_req_valid && d_req_ready` 标识请求握手。`m_sent` 标记当前 MEM 指令的请求已经发出。

- 在 `EARLY_LSU=1` 时，EX 请求被接受并推进到 MEM，`m_sent` 随对应指令保存。
- 在 `EARLY_LSU=0` 时，指令进入 MEM 后才发请求，未接收时保持；接收后设置 `m_sent`，不再重复发出。
- `d_rsp_ready = m_valid && m_sent && !rst`：只有有对应在途指令时才能接收响应。
- `m_finish` 需要响应握手，或者本地异常、非访存操作等独立完成条件。

下面是一个**没有优化重叠**的教学事务时序，便于自己实现和检查：

| 沿 | 请求 valid | ready | `sent`（沿后） | 响应 valid | 说明 |
| --- | ---: | ---: | ---: | ---: | --- |
| 1 | 1 | 0 | 0 | 0 | 保持请求地址/数据 |
| 2 | 1 | 1 | 1 | 0 | 请求接收，不能再重复发送 |
| 3 | 0 | — | 1 | 0 | 等待内存 |
| 4 | 0 | — | 1 | 1 | CPU ready 时消费响应 |

真实项目可以在旧响应完成的同一拍接受下一笔请求；参考源码和测试台处理的事件优先级。它的契约还要求数据请求在背压时保持，项目 [core_main.cpp](../sim/core_main.cpp#L188-L197) 有相应检查。若自己修改门控导致等待中的 valid 或载荷变化，不能用“反正后来又正确”解释过去。

## 9.8 响应报错与精确异常

当 `m_finish` 且有本地异常或外部 `d_rsp_error`，项目形成 `mem_trap`：

```systemverilog
mem_trap = m_finish && (m_exception || ((m_load || m_store_en) && d_rsp_error));
```

本地异常使用保存的 `m_cause/m_tval`；否则 Load 总线错误 cause 5，Store 总线错误 cause 7，`tval` 是原始有效地址。异常 Load 不写 rd。

更微妙的是年龄：如果 MEM 中较老 Load 报错，EX 中较年轻 Store 不能在同一拍接受请求，因此 `!mem_trap` 直接参与早发门控。若你只等到下一拍 flush EX，设备可能早已写入，这是无法靠“撤销寄存器写回”弥补的。

总线错误时设备到底能否已产生副作用，也必须依赖设备/总线契约。不能假设任意第三方外设会在报错前自动回滚。

## 9.9 自己实现与验证

从单发射、一次只允许一个数据事务开始：

1. 在 EX 得到 `addr`、`store_data`、`rd` 和 `funct3`，本地先做对齐判断。
2. 构造对齐总线地址、lane 数据和 wstrb；让请求在等待 ready 时稳定。
3. 握手后保存 `sent=1`，直到响应握手；没有新请求之前不得再次触发写。
4. 成功 Load 提取/扩展后才写 rd；错误形成 trap，不写 rd。
5. 再对接流水线，加入更老异常和重定向门控，最后比较 `EARLY_LSU=0/1` 的退休流。

最小定向用例：

```text
对齐字写后，在 offset 0/1/2/3 分别 LB/LBU，确认符号扩展。
在 offset 0/2 做 LH/LHU，再尝试 offset 1/3，确认不发请求并陷阱。
对每个 lane 单独 SB；对两个合法 lane 做 SH，检查相邻字节不变。
连续两条 Store，分别让 ready 延迟；统计握手恰为 2 次。
Load 后紧跟消费者；响应延迟、成功和错误各测一次。
较老 Load 错误，较年轻 Store 指向带计数的设备；设备写次数必须为 0。
```

结果可先与 [第 3 章的等待 RAM](03-让内存等待.md) 的模型核对，再使用项目 [差分测试](14-验证与调试.md)。第 10 章引入双发射后还要重复这些测试，因为通道编号和程序年龄不一定一致。
