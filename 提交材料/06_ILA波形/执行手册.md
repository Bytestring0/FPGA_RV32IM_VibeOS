# ILA 收尾执行手册（2025.2）

## 现状
- FIC 已是当前网表的探针：32 位 `x_pc[0..31]`，深度 512，时钟 `cpu_clk`
- `add_fic` 通过；两个 96 MHz 工程已建好（96 MHz 对厂商 DDR PHY 路径多约 0.6 ns 裕量）
- 102 MHz 下跑过 5 个种子，最好一次只差 -0.001 ns，未闭合

## 为什么用 96 MHz
102 MHz 时残留违例全部在**厂商 DDR PHY 内部**（不在自研逻辑里），属布局噪声。降到 96 MHz 后这些路径裕量充足，闭合概率接近确定。采集到的波形是同一份 CPU RTL、同一条流水线，只是频率标称为 96 MHz，报告中已注明。

## 两个已就绪工程

| 工程 | 用途 | 上电后行为 |
|---|---|---|
| `npu_system_pds/npu_ila96cm` | **推荐** | TCM 直接烧入 CoreMark 镜像，上电即跑，抓完即走，无需上传固件 |
| `npu_system_pds/npu_ila96` | 备用 | 烧入的是资源加载器，需要再上传固件才能跑 CoreMark |

## 执行步骤

1. 等待构建结束（`run.ps1` 已包含 综合 → 布线 → 位流 三段）。
2. 检查时序：打开 `prj_tasks/pnr_1/report_timing/ag_npu_board_top.rtr`，确认 `Design Summary : All Constraints Met.`
3. 位流位于 `prj_tasks/pnr_1/generate_bitstream/ag_npu_board_top.sbit`。
4. 启动 JTAG 服务：`cd D:/App/pango/PDS_2025.2-ads/bin && ./cdt_js.exe -port 65420`
5. 抓取：`cdt_dbg_shell.exe -file build/contest-validation/ila-capture-2025.tcl`
   - 该脚本会：编程位流 → 导入 FIC → 立即触发 → 等待 2 秒 → 导出 `ila-2025-samples.csv` → 保存 `ila-2025.dprj`
6. 打开 dprj 截图波形，把截图与 csv 放入本目录。

## 若 `dbg_fla_export_wf_data` 报参数错误
先去掉该行，仅执行到 `dbg_save_project`，然后在 Fabric Debugger 图形界面里 File → Export Waveform Data 导出 csv。
